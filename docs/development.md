# Development

Building, testing and the constraints that are not negotiable. Read
[`client-guidance.md`](client-guidance.md) before integrating and
[`threat-model.md`](threat-model.md) before changing anything in `src/`.

> **Reference implementation, NOT audited. Never hold real funds with it.**

## Commands

```bash
forge build          # dependencies are vendored in lib/ (lib/VENDORED.md): builds offline, fetches nothing
forge test           # unit + property/invariant
forge fmt --check    # CI enforces it
python -m pytest scripts -q   # off-chain tooling parity (ruff check scripts for the lint)
bash scripts/two_chain_proof.sh   # the full two-chain proof in one command
cd sdk && npm run typecheck       # strict tsc over the SDK workspace
cd sdk && npm test                # vitest; needs `forge build` done first and the repo venv present
```

The Python tooling wants a virtualenv at the repository root with
`scripts/requirements.txt` installed — `python -m venv .venv && .venv/bin/pip install -r
scripts/requirements.txt`. Four tests in `sdk/test/reconcile.test.ts` spawn the real
`scripts/reconcile.py` from `.venv/bin/python`, so without that venv they fail with a null
exit code rather than a verdict.

## CI

`.github/workflows/ci.yml` runs five jobs:

| Job | What it gates |
|---|---|
| `test` | `forge fmt --check`, `forge build --sizes`, `forge test -vvv` |
| `slither` | static analysis, `fail-on: high`; scoping lives in `slither.config.json` |
| `aderyn` | the gate is the report PARSER, not the exit code — aderyn always exits 0 |
| `python` | `ruff check scripts` + `pytest scripts` — the off-chain tooling builds the blobs the contracts verify, so it gets the same gate the Solidity does |
| `node` | `npm run typecheck` + `npm test`; it builds a venv because of the cross-checks above |

Slither is not expected to be installed locally; the triage of its findings is in
[`static-analysis.md`](static-analysis.md).

## Layout

- `src/GlauxDelegate.sol` — the immutable EIP-7702 delegation target ("frozen forever: keep
  minimal"): the router the account reaches through delegation. Its address is captured at
  construction and is identical on every chain thanks to deterministic deployment.
- `src/GlauxAccount.sol` — the account: threshold verification, update channel, crypto-agile slot.
- `src/GlauxStorage.sol` — storage layout; `src/lib/` holds `SignatureVerify` and `ImplementationCheck`.
- `test/` — unit `*.t.sol` (including `EntryPoint4337.t.sol`, which proves the reentrancy guard
  of the shared `_execute` under an EntryPoint batch), `invariant/` (`GlauxInvariants` +
  `Handler`), `mocks/` (a V2 mock for upgrades), `oracle/` (`P256VerifierOracle`: the vendored
  daimo verifier, etched at the precompile address, TEST ONLY), and the shared fixtures
  `GlauxFixture` / `P256Fixture`.
- `script/Deploy.s.sol` — deterministic deployment.
- `scripts/` — Python tooling: `birth.py`, `submit_birth.py`, `prove_possession.py`,
  `gen_p256_vector.py`, `reconcile.py` (raw-first cross-chain reconciliation, exit 0/1/2/3),
  `aderyn_gate.py`, plus `two_chain_proof.sh`, which runs the whole two-chain proof in one
  command and must be re-run on EVERY bytecode change. The shared Solidity↔Python parity
  fixture is `test/fixtures/storage_parity.json`, generated by `test/StorageParity.t.sol`
  with `GLAUX_WRITE_PARITY_FIXTURE=true`.
- `sdk/` — the TypeScript client (npm workspace, strict, built on viem): seven modules —
  core, signers, birth, execute, gas, eligibility, reconcile. `sdk/src/reconcile/reconcile.ts`
  is a PORT of `scripts/reconcile.py` and the two must reach the same verdict on the same
  state (exit 2 ↔ `unreadable`): touching one alone destroys the cross-check they exist for.
  Solidity↔TypeScript parity fixture: `test/SdkParity.t.sol` → `test/fixtures/sdk_parity.json`.
- `docs/` — reading order: [`specs/2026-07-28-glaux-design.md`](specs/2026-07-28-glaux-design.md)
  → [`specs/2026-07-29-glaux-phase2-account-surface-design.md`](specs/2026-07-29-glaux-phase2-account-surface-design.md)
  → [`threat-model.md`](threat-model.md) → [`client-guidance.md`](client-guidance.md)
  → [`static-analysis.md`](static-analysis.md) → [`deployments.md`](deployments.md).

## Hard constraints

- **`bytecode_hash = "none"` in foundry.toml is untouchable.** The bytecode must stay
  reproducible from the source alone: that value feeds both the canonical CREATE2 address and
  the runtime code hash every birth blob commits to. Changing it invalidates unspent blobs and can
  make birth impossible on chains not yet reached.
- The same applies to the other compilation settings (`evm_version = "prague"`,
  `optimizer_runs = 10000`): they participate in the bytecode and therefore in the canonical
  address. Change them by decision, never as incidental tuning.
- **Two pinned compilers.** `src/` and `script/` compile ONLY with `=0.8.28` and no via_ir;
  `test/oracle/` uses via_ir (the vendored daimo P256Verifier pins solc 0.8.21). The
  `compilation_restrictions` in foundry.toml keep the two worlds apart: do not widen them and
  do not touch the vendored source.
- Dependencies are **vendored** in `lib/`, never submodules or fetches: a fresh checkout must
  build offline.
- `fs_permissions` in foundry.toml is an EXCLUSIVE list: adding an entry means re-granting
  `./out` (read) as well, or `vm.getDeployedCode` — the P-256 oracle etch in every `setUp` —
  dies suite-wide with "path not allowed".
- The fork tests (`P256ForkProbe.t.sol`) want `GLAUX_RPC_*` and `--evm-version osaka`: a fork
  brings the state but the calls run in the local EVM at `prague` spec, where `0x100` is not a
  precompile and EVERY chain looks broken. In pre-flight add `GLAUX_REQUIRE_FORK_CHECKS=1`, so
  a missing endpoint reverts instead of skipping green.
- **Never track `.venv`.** It is in `.gitignore`; inside a separate git worktree it is a
  symlink to the main checkout, and cherry-picked back it points at itself — python then fails
  to start and the reconcile cross-checks go red with nothing wrong in the code.
